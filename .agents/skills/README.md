# Codex / Local Agent Skills Index

Full descriptions of the repo-local skills under `.agents/skills/`. The root
[`AGENTS.md`](../../AGENTS.md) §7 keeps one line per skill (link, trigger, and
any hard rule); the detail lives here so it is read only when choosing a skill.

When you add a skill, register it in both places: a one-line entry in
`AGENTS.md` §7 (the Web portal treats a skill as registered only when its
`.agents/skills/<name>/SKILL.md` path appears there) and a full entry here.
Claude Code project skills are indexed separately in
[`../../.claude/skills/README.md`](../../.claude/skills/README.md).

## Lifecycle

Read the governing `SKILL.md` frontmatter before choosing a procedure. Each skill carries one `metadata` record. Where both agents have an entry, the record lives in the Codex copy and covers both implementations. Claude-only skills carry it in the Claude entry.

| Field | Maintenance contract |
| --- | --- |
| `owner` | The role responsible for the tool or workflow. Route a review to that maintainer through the engineering repository. |
| `status` | `active` for current work within scope, `on-request` for an explicitly requested output or write, `maintenance` for existing targets, `retired` for historical reference only. |
| `entry`, `tools` | The request this skill handles and the actual tool or source used. The skill directory supplies its invocation name. |
| `validation` | A reproducible test or a scenario with an observable result. Live writes or production runs require their ordinary authorization. |
| `reviewed`, `retire_when` | Last review of the contract (quoted YYYY-MM-DD) and the condition to withdraw the procedure. |

Review each record every 90 days and whenever its source, tool, production route or expected output changes. Compare the entry to the owning contract, test a representative case on a fixture or inspect the cited procedure, and update the date after review. This date records a routing review. Operational acceptance belongs to the individual delivery record.
When the retirement condition is met, mark the record retired, direct incoming requests to the supported route, and remove obsolete discovery prompts in the same PR. Run `python -m unittest tests.test_rtd_system_tooling` to check both agents’ entries and the portal view.

## Routing

- For corpus-assisted edits, look up terms and sentences in TM-B, then edit the requested Feishu document or Illustrator source with the available document or design tools. Read back the changed blocks or reopen the edited artwork. For repository tasks, use the owning tool and its verification case. Select Markdown rewrite or highlighted Word preprocessing only when that output is requested.
