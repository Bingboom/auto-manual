# 说明书工作台：生产与复用证据

Status: active

## 第一阶段调查与实施方案

2026-10-02：入口是 `tools/rtd_deliverables.py` 和
`tools/rtd_portal_assets/deliverables.html`，RTD 通过现有 Sphinx portal 扩展渲染。
工程代码只在 auto-manual 修改，合入后由现有镜像同步到 Hello-Docs，再由 RTD 构建。

已核实的数据边界：

- Publish Manifest 是当前冻结发布目录，含目标身份、版本、built_at 与产物清单；
  built_at 是构建时间，不能充当首次上线事件。当前目录不保留完整活动历史。
- Deliverables Snapshot 是飞书最新交付链接快照，未标语言的整本交付不能拆算语言版本。
  印刷包链接不证明逐个 IDML / PDF 文件的可用性。
- Component Registry 定义共享组件，Overview Component Instances 明确绑定型号、区域；
  能证明配置引用，不能证明组件实际进入输出，也不能推断跨语言消费。
- 语料快照含行数和语言覆盖，未提供逐项最终采用记录；月度净变化不是新增事件。
- REV 执行台账记录工程工作流进度；不是构建、人工介入或 Agent 任务事件账本。
- 本次输入未提供可关联的修订、资产版本、后续生产消费与时间顺序证据。

实施范围：新增纯读取聚合模块与独立页面片段，首页按结论、支撑与证据分层：
简短工作入口后展示交付总量与格式入口条形图，再用三类资产关系图呈现资产管理入口，
生产投入与回流以简短状态和操作入口呈现。完整交付矩阵、工作地图和四层详细证据默认折叠。
条形图按各格式的目标交付入口计数，跨格式不相加；来源时间与近期活动记录入口独立显示。每项指标记录身份、单位、范围、
去重、来源、时间、证据及限制。无可信分母时不生成比例。缺失数据分为
Not tracked yet / Unavailable / Not applicable，只有可靠空集才显示 0。

安全网：以现有 Sphinx 页面测试为入口，增加重复目标、空数据、损坏来源、继承组件
引用、未标语言、活动窗口及页面顺序的回归测试。验证依次为 Ruff、针对性测试、
Node UI、完整 unittest、维护门禁、文档链接检查和 Sphinx 页面桌面/移动浏览器验收。
不更改构建 CLI、源表、依赖版本、CI workflow 或说明书正文。

## 页面中的资产管理与消费

第二层按语料库、样式库、模板与骨架组织，每类同时提供管理入口与采用情况。
语料库显示快照中的句对和术语记录，链接到飞书维护位置；样式库链接样式定义和组件
使用指引，组件登记量不能当作样式总数；模板与骨架链接共享模板目录与骨架定义，
骨架按声明身份计数，模板不按文件数累加。页面只提供导航，不直接修改源数据。
产品规格、插图等生产资料仍由页首工作入口提供维护导航。

消费部分分别回答句对/术语、样式/组件、模板/骨架被哪些交付目标采用。
当前只有 Overview 的明确配置绑定可列出；语料最终采用尚未记录，模板/骨架采用
关系尚未汇总，均不能用登记数量推断实际使用。未来接入消费记录时需关联资产身份、
版本、目标与交付证据。三类资产保留各自单位，不合成一个复用百分比。

## 统计契约

- Manual：型号 × 区域；Variant：型号 × 区域 × 已明确语言；多格式、多版本不新增身份。
- Production Targets：发布目录与交付快照可识别目标的并集；未标语言只以整本交付桶列出，
  不计入 Variant / Production Target。该范围不覆盖全部在制任务。
- Published Targets：当前 RTD 构建使用的发布目录目标数，不证明部署已经完成。
- Component 引用：Overview 实例继承解析后，按组件 ID × 型号 × 区域去重；
  明确为配置引用覆盖，排除默认实例推断和语言扩展。只覆盖 Overview 已登记绑定。
- 时间：存量使用来源声明的快照时间；仓库定义使用页面构建时读取的版本与内容哈希。
  近 7 / 30 天采用 UTC、截至本次构建日零点的半开区间 [开始, 结束)。
  没有完整事件账本的指标显示 Not tracked yet；不读取文件 mtime 推算事件。
- 快照读取失败单独显示 Unavailable；注册数不等于实际消费，链接数不等于逐格式文件数。

## 后续记录缺口

第二阶段优先扩展已有 revision ledger / release records，连接 correction ID、asset ID、
asset version/hash、消费该版本的生产记录、目标身份、时间与证据 URL。需要同时有覆盖窗口
和事件身份，才能区分首次发布、重复发布、尝试与重试，报告可靠的活动零值。
第三阶段只有在产品复杂度、内容单位和生产阶段可比较后，才分析新增内容、人工与返工趋势。
当前不量化节省工时，不宣称已证明生产成本下降。

## 活动指标的记录前提

以下为未来可靠记录接入后的计数口径，当前均为 Not tracked yet，不填 0。

| 指标 | 唯一身份与单位 | 纳入 / 排除 |
| --- | --- | --- |
| New Manuals / New Language Variants | model-region / model-region-lang 的首次创建事件 | 要有完整基线；排除新增格式、重建和改名 |
| Build Attempts / Build Retries / Successful Builds | task ID + attempt ID，各一次执行 | 重试独立；成功只认终态；不当成新增资产 |
| First Published Variants / Repeat Publications | Variant + version + publication receipt ID | 区分首次和重复；构建时间不作上线时间 |
| Review Corrections / Backports | correction ID / backport ID | 修订与回写动作分开；排除 dry run |
| TM / Shared Component Additions | 稳定资产 ID 的创建事件 | 排除更新、删除、复制与重复导入；不采用净增长 |
| Agent Executions | task ID + attempt ID | 尝试不等于任务；成功自动任务须有可靠终态与人工介入记录 |

所有窗口均以 UTC 且使用同一半开区间；分母不适用时保留 Not applicable。
每条事件接入前需有时间、来源及证据入口，不能通过阶段总量推测关联。
