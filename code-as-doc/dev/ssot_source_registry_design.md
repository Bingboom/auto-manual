## 1. 要解决的问题

系统建设页和交付物页上的每个数字、每个状态都有来源，但来源都写死在各页面的代码里：
发布清单的路径、台账的路径、快照的文件名、对应哪张飞书表、多少天算过期、取不到时显示什么。

- 看页面的人不知道一个数字以哪里为准，也不知道它有多新。
- 新增一个页面块，要在代码里再写一遍取数和降级逻辑。
- 以后多个 agent 分头干活时，没有一个地方告诉它们"这件事以哪里为准、多久算过期"。
  各读各的副本，结论就会互相冲突。

## 2. 做法

新增一份登记文件，每个数据域登记一条，写明五件事：

| 字段 | 含义 |
| --- | --- |
| 数据域 | 页面上的一类事实，例如"发布目标" |
| 权威来源 | 以哪里为准：仓库文件、Hello-Docs 文件或飞书表（飞书表写环境变量名，不写 token） |
| 读取方式 | 构建时直接读，或者读提交进仓库的快照；快照写明导出命令 |
| 新鲜度 | 快照多少天算过期；直接读的写"随构建" |
| 取不到时 | 页面怎么显示：无数据、待复核，或不显示这一块 |

页面代码按数据域取来源和过期规则，不再各自写死。`check` 负责核对三件事：

- 每个页面块都引用了登记里的数据域；
- 每条登记的来源确实存在；
- 快照没有过期。

## 3. 第一版要登记的数据域

按现有页面整理，一共八个：

| 数据域 | 权威来源 | 读取方式 | 新鲜度 | 取不到时 | 用在 |
| --- | --- | --- | --- | --- | --- |
| 发布目标 | Hello-Docs `docs/publish/publish_manifest.json` | 构建时读 | 随构建 | 无数据 | 系统建设页的发布数字、交付物页的网页手册列、"现在就能用" |
| 执行进度 | `code-as-doc/dev/manual_revitalization_execution.md` | 构建时读 | 随构建 | 执行台账当前不可读 | 当前重点的进度、阶段门、"当前在做" |
| 语料规模 | 飞书翻译记忆库（`$FEISHU_TRANSLATION_MEMORY_BASE_TOKEN`） | 快照 `system_workspace_corpus.json`，由 `corpus-export` 导出 | 45 天 | 无数据 | 语言资产 |

## 4. 和 IR 共享、多 Agent 调度的关系

- **IR 共享（REV-39、REV-40）**管的是说明书内容本身：网页、IDML、Word、PDF 以同一份冻结整本包为准。
  REV-39 摸出的内容来源链，会成为登记里新增的"说明书内容"数据域。两件事互不阻塞。
- **多 Agent 调度（REV-45）**建在本登记上。任务状态和交接记录也作为一个数据域登记，权威来源是台账加交接记录；
  agent 按登记找来源、判断是否过期，不各自保存一份副本。

## 5. 放在哪、谁能改

- 登记文件放在 `tools/rtd_portal_assets/`，和状态配置放在一起，构建时读得到。
- 只写来源的位置和环境变量名，不写凭据或表 token。
- 改动走 PR，`check` 通过才合。

## 6. 定稿后的实施步骤

1. **登记文件和 `check`**：只登记、只校验，页面输出不变。整站前后对比要求逐字节一致。
2. **页面改为从登记读取**：系统建设页和交付物页的新鲜度和降级文案都从登记读。整站对比只允许措辞统一带来的差异，并逐处说明。
3. **公开"数据来源"小表**：系统建设页列出每个数据域的来源和快照日期（第 8 节第 2 条已定）。
4. **多 Agent 调度**：REV-45 设计时直接引用本登记。

## 7. 不做

- 不把飞书实时数据搬进 RTD，RTD 仍然不读飞书。
- 不替代台账，也不替代各页面自己的内容配置。
- 这一版不改数据本身，比如不修构建表里错误的产品名称。
