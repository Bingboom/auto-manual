## 3. 可编辑性实测结果

工具：PyMuPDF 1.28.0 / MuPDF 1.29.0（仓库 `.venv`）。全部为只读分析。

### 3.1 原生可编辑性：保留

| 标记 | 出现次数 | 含义 |
| --- | --- | --- |
| `AIPrivateData` | 107 | Illustrator 私有数据保留 |
| `PieceInfo` | 23 | 每页一份，原生对象结构在 |
| `AIMetaData` | 1 | Illustrator 元数据在 |

这是真正的 Illustrator 原生 `.ai`（PDF 兼容），不是压平后的 PDF。
对照：仓库 recipe `normalization.forbidden_pdf_markers` 正是把这三个标记列为
**规范化输出**中必须消除的对象——两边方向相反且各自正确，母版留着、导出物去掉。

### 3.2 按计划 §3.2 分级

| 等级 | 页数 | 页码 |
| --- | --- | --- |
| 矢量 + 活文字 | 19 | p01–p02、p04、p06–p20、p23 |
| 混合矢量/位图 + 活文字 | 2 | p21、p22（App 设置页） |
| 纯矢量、无文字 | 2 | p03、p05（前部整页图，各仅 1–2 个路径对象） |
| 矢量 + 转曲文字 | **0** | —— |
| 位图封装 SVG/伪矢量 | **0** | —— |

- 全书 **27,519 个活文字字符 / 953 个文字 span**，没有任何一页是转曲文字。
- **35,512 个矢量路径**，其中 p17（车充/太阳能充电）单页 27,304 个，占全书 77%。
- 只有 10 张内嵌位图，全部集中在 p21/p22。

结论：这份母版达到计划 §3.2 的首选形态（矢量 + 活文字），可以作为
「合格设计交付」的正面样例。但下列四项必须同时记入交付说明，否则等级会被高估。

### 3.3 必须一并声明的四项限制

**(1) 全书 K 单色，没有任何彩色。** 23 页逐页采样，彩色像素数为 **0**。
内嵌的 10 张位图颜色空间是 `/Separation /Black /DeviceCMYK`（单油墨黑版），
包括 p21/p22 的两组手机 App 截图——它们在母版里**本来就是灰度**，不是渲染丢色。

这对印刷是正常的（单色说明书），但 Web 是彩色媒介。如果 Web 未来直接消费设计
交付物，要么接受灰度 App 截图，要么要求设计另出彩色变体。这是需要业务裁决的
事项，不能靠工具默认继承。登记为 AS-D05 子项。

**(2) 图层没有语义命名。** 只有 3 个 optional-content 图层，名字是 Illustrator
默认的 `图层 1` / `图层 2` / `图层 3`。计划 §3.1 要求验收人「检查对象、分组和图层」，
当前母版无法据图层名判断哪层是机身、哪层是标注、哪层是引线。
交付说明必须把图层命名列为要求项。

**(3) 字体全部子集内嵌，编辑仍需本机装字体。** 12 款字体全部内嵌，且都带 6 位
子集前缀（如 `QNKZYN+Gilroy-Regular`）。子集内嵌保证**显示**正确，但设计同事要
**新增字符或改文案**时，本机必须装有原字体，否则会触发替换。

| 字体 | 类型 | 角色 |
| --- | --- | --- |
| Gilroy Regular / Bold / Medium / SemiBold / Heavy | Type1 / CFF | 设计正文字体（商业字体，需授权） |
| SegoeUISymbol | Type0 / TTF | 32 个 span，符号回退，非设计选型 |
| HelveticaNeueLTCom-Cn、TimesNewRomanPSMT | TrueType | 各 2 个 span，疑似残留 |
| AdobeSongStd-Light、NotoSansSC-Thin、NotoSansJP-Regular、FZLTZHK--GBK1-0 | Type0 / TrueType | **各 1 个 span**，中日文字体出现在欧规英文母版中，几乎确定是残留 |

后两行是可以直接反馈给设计的清理项：欧规英文母版不应依赖四款中日文字体和
两款疑似残留西文字体。这不影响当前印刷，但会让「字体依赖清单」失真。

**(4) p17 复杂度是导出风险点。** 单页 27,304 个路径。计划 §4.1 要求
「复杂滤镜、透明度、裁切、描边和文字布局按实际消费端验证」——这一页是最可能在
SVG 导出后体积暴涨或渲染变慢的对象，A3 的 Web 验收要单独看它。

### 3.4 自包含性：通过

外部文件引用（`/FileSpec`、外部 `/F`）计数为 **0**。母版不依赖设计同事本机的
链接图片或绝对路径，满足计划 §3.1「在干净目录打开，确认不依赖设计人员本机绝对路径」
的机器可验部分。人工在干净目录打开的确认仍待做。

### 3.5 视觉抽查

已渲染 p08（产品概览，含本地化标注与引线）、p17（最复杂页）、p21（混合位图页）
三页 150 dpi 位图并逐张查看：版面完整、文字可读、引线对位正常、
UK 制式插座与 `230 V~ 50 Hz` 标注与欧规相符，未见缺字或字体回退方框。
渲染件在本轮 scratchpad，不入库。

## 4. 字段映射：可编辑性信息落到现有三张表

计划 §3.3 要求「先映射到现有字段或现有 manifest；只有无法表达的项目才提出新增字段」。
按 [`data/asset_base_bindings.json`](../../data/asset_base_bindings.json) 的现有字段核对：

| 本轮要记录的信息 | 现有可承载字段 | 是否够用 |
| --- | --- | --- |
| 母版文件与字节 | `04_资产源文件.source_file`（附件）、`source_sha256` | 够 |
| 母版修订 | `document_revision`、`registry_revision` | 够 |
| 页数与页面尺寸 | `page_count`、`page_width_mm`、`page_height_mm` | 够 |
| 归档状态 | `archive_status` | 够 |
| 文字政策 | `04_资产定义.text_policy`、`04_资产导出物.text_policy` | 够 |
| 语言维度/变体 | `language_dimension`、`language_variants`、`locale`、`web_locale` | 够 |
| 适用范围 | `model_scope`、`region_scope` | 够 |
| 审核与可构建 | `gate_status`、`build_eligible`、`visual_review_required` | 够 |
| 导出物格式与哈希 | `format`、`content_sha256`、`expected_sha256` | 够 |
| **可编辑性等级**（§3.2 四级） | 无对应字段 | **缺** |
| **字体依赖清单**（含是否可随包提供） | 无对应字段 | **缺** |
| **色彩模式**（K 单色 / 彩色） | 无对应字段 | **缺** |
| **图层命名是否合规** | 无对应字段 | **缺** |
| 设计侧画板结构 | 钉钉 `翻译源文件描述` 已有 | 够，但在另一个 Base |

结论：三张表覆盖身份、版本、范围、审核、哈希，**不覆盖可编辑性本身**。
最小扩展建议是在 `04_资产源文件` 加三个字段（可编辑性等级、色彩模式、字体依赖），
`notes` 暂可承载但不可查询、不可闸门。本文只提出建议，
**不执行任何表结构变更**——按仓库现有线上写入流程与审批门执行。
