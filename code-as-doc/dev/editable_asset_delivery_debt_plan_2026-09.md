# 可编辑插图资产与设计交付计划、债务账本

- 登记日期：2026-09-08
- 状态：`deferred`，本轮欧规单语 Web 上线验收完成后再启动试点
- 路线图归属：Workstream Z；逐项债务唯一账本：§7
- 目标：设计同事可按统一标准交付插图，资产库中的文件也可交回设计同事继续编辑；
  构建和发布使用有版本、可追溯的导出物。

## 1. 本轮决定与范围

操作者确认采用“可编辑母版 + 发布导出物”的资产管理方式，希望插图未来成为设计
同事的正式交付物。本次授权是写计划、登记债务；实施、资产上传、线上表修改、
设计交付通知、批量转图和重新发布均未启动。

保留原始 AI 或 SVG 母版，按目标导出 SVG/PNG/PDF，并通过资产编号与版本关联。
SVG 的可编辑性按实际对象检查，文件扩展名不能作为唯一证据。原生 AI 的图层和效果
需要保留时同时归档 AI；不承诺 SVG 能无损承载所有原生编辑结构。

共享图与机型专用图采用“共享基础资产 + 一层显式覆盖”。继承发生在资产选择层，
每个变体仍有独立、完整的可编辑母版；不在本轮引入 SVG 图层自动继承或差异合并。
覆盖约定及试点验收见 §4.2，相关待办集中登记为 AS-D07。

优先级仍是当前欧规单语上线。上线后以一本已有说明书做资产闭环试点；该工作可
独立于 [ManualIR 生产入口迁移](manual_ir_production_migration_debt_plan_2026-09.md)
安排，不要求先完成四端 IR 重构，也不作为当前上线的新增阻塞条件。

## 3. 设计同事的目标交付标准

以下为待试点验证的交付约定，当前不视为已向设计团队发布的新制度。
设计同事负责可编辑源和设计内容；资料负责人确认适用范围及图内文案；
资产工具负责编号关联、哈希、导出清单及技术校验。哈希不要求设计同事手工填写。

### 3.1 一个资产交付包包含什么

| 内容 | 要求 | 验收人/方式 |
| --- | --- | --- |
| 可编辑母版 | AI 或真正的矢量 SVG；原设计来自 AI 且需原生结构时保留 AI | 设计人员用约定编辑器打开，检查对象、分组和图层 |
| 可修改的文字 | 需本地化或日后改字的文字在母版中保留文本对象；记录字体名称/版本及缺失依赖 | 选中一段文字试改，再保存、重开验证 |
| SVG 交换副本 | 适合交换的矢量图提供 SVG；复杂原稿若无法保持效果，明确适用限制并保留原生源 | 检查路径、填充、描边、裁切及效果，不把有损导出标为无损母版 |
| 发布导出物 | 根据本轮消费端交付 SVG，及确有需要的 PNG/PDF；发布副本可以采用已声明的转曲策略 | 浏览器/实际输出端与设计预览比较 |
| 预览 | 一张便于浏览和评审的预览图，与交付版本关联 | 多维表中能快速识别内容 |
| 交付说明 | 资产名称、用途、型号/区域/语言、修订说明、母版与导出物关系、编辑依赖 | 资料负责人确认业务含义，工具检查必填项 |
| 附属资源 | 实际依赖的链接图片随包归档或自包含；字体文件仅在允许提供时打包，否则记录获取/替代说明 | 在干净目录打开，确认不依赖设计人员本机绝对路径 |

目录仅为交付示意，正式打包继续复用现有 intake 清单，不另建重复格式权威：

```text
<asset_key>/<revision>/
    source/       原生母版及实际依赖
    editable/     适合交换时提供的可编辑 SVG
    exports/      按语言和用途区分的 SVG、PNG、PDF
    preview/      评审预览
    manifest      现有资产工具生成的文件、来源、角色与哈希清单
```

### 3.2 可编辑性必须分级标明

| 类别 | 含义 | 处理原则 |
| --- | --- | --- |
| 矢量 + 活文字 | 图形为路径/形状，需要修改的文案为文字对象 | 首选设计交付形态，仍需实际打开检查 |
| 矢量 + 转曲文字 | 图形和字形可改，字形已不是可直接输入的文本 | 可作为发布副本；应关联保留活文字的母版或明确文字编辑债 |
| 混合矢量/位图 | 部分对象可编辑，部分为嵌入或链接的位图 | 声明位图范围及原始资源，不标成全矢量 |
| 位图封装 SVG | 主要内容只是 PNG/JPG 放进 SVG 容器 | 作为位图资产归档，不能验收为可编辑矢量母版 |
| 原生源待补 | 只有现成 PNG/PDF 等交付件，尚未取得可编辑设计源 | 记录来源与待补事项；不自动描摹后销账 |

固定机身丝印、logo、本地化标注分别声明。保持发布内容的完整性：Web 成品整图可用
SVG 承载完整文字和引线；规格、故障排除等结构表格继续由文档组件生成，不因资产化
变成整表截图。AI/SVG 母版和发布副本可以采用不同文字策略，必须保持可追溯关联。

### 3.3 设计交付表单的最小业务信息

建议向设计人员展示：名称、用途、适用型号、区域、语言/共享声明、修订说明、母版
附件、可编辑性说明、发布导出物和预览。专用变体还需说明覆盖对象；从已有设计
派生时记录原母版及修订，不能用设计来源替代构建覆盖关系。技术字段由入库工具补充。

需要“负责人、交付修订、母版角色、可编辑性等级”等信息时，先映射到现有字段或
现有 manifest；只有无法表达的项目才提出新增字段。这里是设计要求，不是已经落地
的 Base schema，任何表结构变更按仓库现有流程实施。

## 4. 身份、版本、存储和构建规则

### 4.1 身份、存储与冻结消费

逻辑身份使用稳定 `asset_key`；物理文件身份包含源修订、语言、用途、格式及内容
哈希。沿用现有 key/scope 规则，不用原始文件名承担唯一性，也不为每次使用重复建资产。
某图确实只适用于特定型号时必须声明范围，不因视觉相似自动共享。

设计交付形成新修订，保留旧修订及其附件/资产包。已发布说明书固定引用所用版本，
不得通过覆盖同一附件、修改一个本机路径或“自动取最新”使旧版本用图悄然变化。

资产本体可使用独立附件，也可存于不可变 ZIP 附件中。独立 SVG/预览适合设计查阅；
批量归档允许 ZIP + 逐文件索引，但每个条目必须能定位并取回真实字节。
试点阶段需确定权威存储及完整性策略，避免附件与 ZIP 成为两份可独立修改的真身。

目标链路：

```text
设计交付母版与导出物
    → 现有三表归档、版本关联和验收
    → 下载指定版本，校验哈希，形成构建缓存/冻结快照
    → asset:<asset_key> 解析为本次明确的导出版本
    → Web / 其他消费端从包内取图
    → 发布用图清单 → 哪本说明书的哪个版本使用了哪张图
```

下载器的缓存按不可变身份/哈希命中；文件缺失或哈希变化明确失败，不能用过期缓存
或其他语言的图片掩盖错误。网页使用随站点发布的文件，不直接热链飞书私有附件。
将“已归档”“允许用于某目标构建”“已发布使用”分别记录，上传成功不代表已交付。

SVG 发布副本应有确定的尺寸/viewBox、完整资源及明确字体策略；不得依赖本机文件
或运行时远端资源才能显示。复杂滤镜、透明度、裁切、描边和文字布局按实际消费端
验证。某端不适合直接消费 SVG 时，可从同一母版派生经校验的 PNG/PDF，并保留关联；
母版仍保持可编辑。不同格式的 hash 各自记录，不要求不同文件格式字节相同。

### 4.2 共享基础图与一层机型覆盖

模板保持引用既有逻辑用途的 `asset:<asset_key>`，由同一个 resolver 选择目标实际资产。
基础图与专用图各自拥有唯一 `asset_key`，专用图通过 `override_for` 指向基础图。
下表沿用已有 LCD key 说明关系，适用范围仍需在试点逐项确认，不代表新增上线授权：

| 模板请求 | 目标 | 预期资产选择 |
| --- | --- | --- |
| `asset:lcd/lcd_map` | 明确核准可使用共享图的目标 | `lcd/lcd_map` 的冻结版本 |
| `asset:lcd/lcd_map` | JBP-2000B，且区域/语言适用 | `lcd/jbp2000b/screen` 的冻结版本 |
| `asset:lcd/lcd_map` | JBP-3600A，且区域/语言适用 | `lcd/jbp3600a/screen` 的冻结版本 |

实施时保持以下边界：

1. **共享范围显式确认。** 通用箭头、操作图标可按确认范围复用；机身、接口、插座、
   屏幕等图不能因外观相似自动共享。试点核对已有 `ALL` 声明，不将历史宽范围视为
   设计适用性已确认；只处理本次目标，不借机开展全库清理。
2. **只做一层覆盖。** 区域、机型、语言共同限定适用条件，不按“机型 > 区域 > 语言”
   隐式排序；两个覆盖同时命中就报错。需要多个区域变体时均直接指向基础 key，
   明确不重叠的适用范围，不使用“共享 → 系列 → 机型 → 区域 → 语言”嵌套链。
3. **回退必须有业务依据。** 无覆盖命中时，仅允许使用已确认适用的基础图。对必须
   使用专用图的目标，在既有目标源契约/验收清单中明确要求并由构建检查，不用
   `ALL` 默认值掩盖专用记录缺失。命中专用图后若文件缺失、未通过审核、语言/格式
   不足或哈希不符，明确失败，不再静默回退共享图或其他机型图。
4. **设计派生与构建覆盖分开记录。** “由哪份母版、哪个修订派生”描述设计来源；
   `override_for` 描述替代哪个用途的资产。两者不必相同。专用图保存完整 AI/SVG
   母版及依赖，不修改共享母版；基础图更新不自动改写专用图的设计内容。
5. **冻结实际选择。** 复用现有用图 manifest，保留请求 key、实际选中 key、目标、
   源/导出修订、语言、格式和 hash。字段缺口先在既有清单补齐，不建立平行账本。
   发布重播使用冻结映射与文件，不依据最新注册表重新决定覆盖；覆盖关系或适用
   范围后来改变，也不得改变旧发布版本用图。
6. **关系入库复用现有体系。** 先核对三表与 manifest 如何表达 `override_for`、
   母版派生来源及版本，确认同步所有权；确需字段扩展时提交最小变更方案，按现有
   线上写入流程执行。尚未核实的线上字段不能记为已存在或已迁移。

独立机型新增用途、没有共享基础的图直接登记独立资产，不为使用“继承”强造父图。
首期不开发 SVG 内部对象覆盖引擎；设计同事可以复用母版创作，交付时仍提供可独立
打开、编辑、保存重开的完整变体文件。

### A2：试点文件归档与版本回取（deferred；依赖 A1）

准备明确的源、定义、导出物记录及附件清单，按现有 live-write 规则展示变更、确认
后入库。逐记录读回，附件 token 非空；下载实际文件，校验源和每个导出物的哈希。
演练新增修订后仍可取回旧修订，不重复创建已有逻辑资产，也不覆盖旧版附件。
读回共享/专用关系及范围，核对母版派生来源与修订；设计专用图的提交不得覆盖
共享母版或其他机型的源/导出文件。

退出：试点文件全部可从云端恢复，源/导出关系和版本无歧义，设计包可离开原电脑使用。
“已记录路径”或 API 上传成功不能代替下载与编辑验证。

### A3：一本说明书从云端资产快照构建（deferred；依赖 A2）

复用现有 resolver、finalizer、缓存和发布血缘；先厘清 Base 元数据、仓库导出索引及
文件字节的所有权，再补下载/物化步骤，不用第二个同步器互相覆盖。
优先接当前 Web 入口，原文件不改字节地归档回取，先证明取图来源改变不改变产物。

需要 PNG→SVG 替换时另记明确的资产修订与视觉差异，不能与搬运闭环混在一起
宣称零变化。验证原本机文件不可读时仍可构建；网页图片、语言、尺寸和布局通过
桌面/移动端检查，使用清单可定位具体导出版本。

退出：试点整本的实际引用均可解释，新增修订不会影响旧发布版本；缺图、错语言、
坏 hash 有有效失败测试。仅“SVG 被注册为可用格式”不足以证明某个渲染端已接通。
覆盖机制另需验证：合法共享、指定机型覆盖、区域/语言隔离、必须专用但记录/文件
缺失、未审核覆盖、重复命中和嵌套拒绝；对不受影响的目标做聚焦解析回归即可。
在试点更新共享/覆盖修订及选择关系后重播旧冻结包，证明实际选中 key 和文件 hash
保持不变。以上是实施阶段验收要求，本次文档登记不声称这些用例已经执行通过。

### A4：设计交付闭环与有限推广（deferred；依赖 A3）

由设计同事按标准提交一个真实小修订，完成入库、回取、构建与差异验收；反向从
资产库下载该包给指定验证者二次编辑，验证其可作为后续设计工作的交付文件。
交付给他人的发送动作另按操作者明确指令执行，本计划不自动发送文件或通知。

根据实际用图清单生成“说明书版本/章节 → 资产/导出版本”的引用关系，优先复用
现有 manifest。需要在 Base 展示时再设计查询视图或使用记录，避免手工维护两份账。
本轮闭环后按需要增加目标或消费端；IDML/Word/PDF 的兼容性逐端验收，不自动声称
SVG 跨所有软件无损。大规模历史图重绘、自动描摹和全量迁移留到独立排期。

## 6. 验收材料与资源安排

- 设计交付验收：源文件、预览、编辑器版本、对象/文字编辑及保存重开结果、依赖清单。
- 云端归档验收：三表的记录定位、实际附件/包成员、下载 hash、旧新修订恢复证据。
- 构建验收：目标、代码提交、输入快照、资产清单、实际 Web 产物及视觉比较。
- 覆盖验收：核准适用范围、请求/实际资产映射、共享和专用选择、冲突/缺失失败，
  以及关系变更后旧冻结包重播和其他目标解析不受影响的证据。
- 引用追溯验收：能够回答“谁交付、哪份母版、哪个修订、哪本说明书的哪个版本用过”。
- 文档变更按文档检查验证；代码阶段跑聚焦测试及根 AGENTS.md 要求的完整验证组合，
  聚焦失败定位后再重跑相关测试，不重复未受影响的全量实验。
- 默认一个主窗口，阶段结束短审查；优先复用现有产物/清单，不启动大规模并行审计。
- token 紧张时停在阶段边界，保留交接记录与未完成项；不以降低原生编辑和视觉验收
  标准节省资源。未指定数字预算，后续每次只启动当次明确的阶段。
