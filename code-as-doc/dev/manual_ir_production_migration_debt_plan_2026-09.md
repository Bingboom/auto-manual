## 5. 目标结构与不变量

```text
冻结源快照 + 模板/配置 + 现有骨架/页面规划
    → 公共整本组装（完整 flow、ComponentSpec、逻辑顺序、来源）
    → 同一个冻结包（IR + 素材 + 各端所需已解析契约）
        → Web adapter → 现有网页发布产物
        → IDML adapter → 现有排版组件与物理页面计划
        → Word adapter → 可编辑 DOCX
        → LaTeX/HTML adapter → 现有 Sphinx/LaTeX 排版输出
```

- 同一构建目标组装一次；正文、参数、警告、表格及组件身份的权威在公共语义层。
- 稳定 `source_ref`、语言及逻辑顺序沿用已有规划；不在本轮改已有文件命名和评审路径。
- 章节/组件组合与物理跨页、框坐标分开。复用现有 PagePlan 和 target assembly，
  不把完整 IDML 几何合同直接要求 Web 消费。
- Web 的带字整图与 IDML 的可编辑标注允许不同呈现；公共包保留完整文字与素材角色，
  按输出端声明选择冻结变体，禁止通过删公共内容或跨语言借图取得表面一致。
- 先评估复用 v2；需要扩展 schema 时单独说明必要性及兼容办法，不预设必须新建 v3。
- 历史 v1/v2 文件保留显式读取兼容；不得在读取时偷偷升级、重写哈希或跳过未知语义。
- 重放可以使用固定版本的渲染器、字体和引擎，必须记录版本；它不能靠回读原 RST/CSV、
  活 Base 或未冻结的目标合同补内容。IR 生成的临时 RST/TeX 是允许的输出端载体。
- 架构迁移不扩大内容治理范围；长正文/法规文本的所有权仍遵守
  [System Evolution Strategy](../architecture/System%20Evolution%20Strategy.md)。

## 6. 分阶段实施

### P0：上线收尾与基线封存（pending；沿用上线任务）

按 §3 收齐本轮上线证据。保留实际源快照、Web 输出、IR/素材、发布版本、关键截图，
另准备 JBP-2000B/JP/ja 与 JE-1000F/US 回归所需的来源说明。
线上发布内容、review-asis 输入和 fixture 输入分别记录，不混为同一基线。

交付物：基线索引及 §10 记录。退出条件：能准确定位本轮已发布版本，并明确迁移
试点使用哪一套源。此阶段不为了规划运行新一轮全量构建或大量代理审计。

### P1：公共边界发现与冻结（deferred；启动后第一个开发阶段）

只追踪 §2 的实际调用链，列出“源选择 → 解析 → 组装 → 渲染 → 文件输出”职责。
核对完整内容与 Web normalization 的先后关系、IDML 所需语义、素材变体、
source_ref、hash 和 PagePlan 字段。复用现有 ManualSource/ManualIR/ComponentSpec。

交付物：一张输入/输出契约表、一个代表性冻结包样例、调用路径迁移清单和试点差异表。
试点章节优先选故障排除或规格表，并覆盖普通正文、富文本及一处素材引用；
不从复杂总览几何开始。样例需含非源语言文本，不能只验证英文合成结构。

退出条件：主开发与阶段审查能说明哪些信息是公共语义、哪些属于输出端、哪里可能
丢信息；没有通过重建另一套 planner 或复刻母版几何解决边界问题。

### P2：公共组装与一个真实章节闭环（deferred；依赖 P1）

在输出专属转换前生成完整公共语义与素材角色，冻结所需契约。接入一个真实章节的
Web 和 IDML 消费路径；IDML 尽量把 flow/ComponentSpec 转成现有排版组件的输入。
新目标路径遇到不支持内容必须明确失败，不能静默回退旧 parser。

交付物：同一个包生成的网页片段和实际 IDML、内容/组件清单、禁源读取测试、
旧新输出差异。章节可作为中间验收单元，但必须接在实际生产调用链上。

退出条件：禁用旧源解析函数后章节仍出产物，文字/表格/素材角色完整，IDML 在
InDesign 中实际打开检查。通过后才扩到整本，不能用一个新 demo 入口宣布生产迁移。

### P3：JBP-2000B/JP/ja 整本 Web/IDML 同包（deferred；依赖 P2）

把同一试点覆盖到所有章节与其真实结构；同时保留 JE-1000F/US 的现有行为回归。
原始源文件、未冻结合同和旧解析入口不可用时，两端仍从同一冻结包生成整本输出。
需要的 source metadata、图片、布局合同和字体依赖不得靠本机残留产物补齐。

验收材料包括整本语义清单、组件/图片覆盖、语言、目录/锚点、IDML story 与溢出
检查、浏览器与 InDesign 视觉证据。排版差异必须逐项解释；不能重算 golden 或
放宽参考样式/素材哈希来取得通过。

退出条件：IR-D01/D02/D05 的试点子项达到销账标准；IR-D06 已具备 Web/IDML
实际产物证据；迁移目标的旧入口停止调用。报告明确“一个目标闭环”，不扩大为
所有型号、所有语言或四端全部完成。此处是第一轮正式停止点，重新评估资源后续排期。

### P4：Word 生产入口（deferred；第一轮验收后再启动）

实现同包到 Word 的正文、列表、富文本、表格、图片与页面角色转换，保留参考样式和
既有导出能力。覆盖非 Web 的真实文档分支，梳理现有 bundle/html/latex 来源模式，
明确本轮支持集及仍留兼容的路径，避免只迁移一个不被生产配置选中的分支。

退出条件：实际 DOCX 可打开、正文及表格可编辑；迁移目标禁源冷重放通过，
没有漏页、漏脚注、错误分页/页眉页脚。IR-D03 按实际支持范围登记，未覆盖模式继续记债。

### P5：LaTeX/PDF 与普通 HTML（deferred；依赖前述公共契约稳定）

从公共包生成受控的渲染输入，可使用生成的 doctree、RST 或 TeX，复用现有引擎。
先处理一类共享表格/警告和正文，再扩到试点整本；按源文件/块登记 raw/only 的语义
归属。内容条件由公共组装解析，输出呈现条件由 adapter 处理。

退出条件：实际 PDF/HTML 由同包生成且不回读原始源；内容清单、文字可见性、
表格、分页和字体通过验证。不能通过强制各端相同页数来替代各格式自身的正确性。

### P6：退役与有限扩展（deferred；按端实际完成范围执行）

逐项确认旧入口的生产调用者、历史兼容调用者和测试引用，移除已无必要的重复解析。
需要大块删除、公开接口变化等操作仍按根 AGENTS.md 的明确规则执行。
完成记录必须列出退役函数/模块、剩余调用者及兼容原因。

待试点四端具备实际产物证据后，再选一个结构不同的目标验证可扩展性；
优先复用已封存的欧规单语上线目标，其次按结构需要评估 KR。不得自动全型号铺开。
阶段完成时更新债务、路线图和维护日志，保留旧包读取及回滚材料。

## 7. 验收标准与验证成本

| 验收层 | 必须证明 | 不能作为替代证据 |
| --- | --- | --- |
| 公共语义 | 相同正文、参数、警告、表格行及逻辑组件顺序；差异可定位 source_ref | 相同 schema 名、相同文件名或 import 命中 |
| 输入隔离 | 全新进程/隔离目录从冻结包出实际产物，原始源及未冻结合同不可读 | 主进程缓存、现有 `_build` 或只 mock 最外层函数 |
| 资产闭合 | 包内引用均存在且 hash 一致，语言/角色正确，损坏/缺失明确失败 | 图片张数相等或路径存在 |
| 输出正确 | 每种格式分别对照自身冻结基线，内容完整、链接有效、可编辑性符合要求 | 四端 adapter 返回非空、跨格式强求字节/像素一致 |
| 原生排版 | 浏览器检查桌面/移动端；IDML 用 InDesign 检查溢出、字体、行距和可见内容；DOCX/PDF 实际渲染检查 | XML 中写了某属性、文本抽取成功或 golden 自动重建 |
| 路径退役 | 迁移目标禁用旧解析器仍成功，未迁移/历史路径显式登记 | 全仓 grep 次数下降 |

开发循环先跑触及模块的 lint 和聚焦行为测试；每个 PR 定稿后集中跑根
[AGENTS.md](../../AGENTS.md) 要求的完整验证组合。完整单测、Ruff、边界、文档链接、
对应目标 check，以及受影响的 publish/diff/release 验证按改动适用，不无故重复。
新增修改、失败或未解决疑点才触发重跑。原生视觉验收不能因 token 紧张被免除；
资源不足时缩小阶段范围并保持未完成状态。

本次仅新增规划/债务文档及索引，执行文档链接检查和 diff 检查；没有运行实施阶段
的测试、整本构建或任何发布命令。未来命令以启动时的仓库规则与 `build.py` 为准。

  边界明确的实现或阶段审查可用 GPT-5.6 Sol high。启动时再看可用模型与剩余额度，
  这些是排期建议，不是成功保证或固定价格承诺。
- 公共契约稳定且存在互不重叠的适配任务后，才评估第三个短期窗口；多窗口仅在
  操作者明确启动后创建。schema、组件身份、组装规则保持单一写入负责人。
- 所有开发窗口独立 worktree、分支和输出目录。审查固定到提交 SHA；产物构建与
  InDesign 检查使用独立目录，避免不同任务覆盖同一本书的结果。
- 每阶段保存短交接记录：基线、已完成范围、下一步、失败点、验证命令/日志路径。
  恢复任务先读交接和增量 diff，不重新读取全部历史、不重复已通过且未受影响的实验。
- 常规工具输出只保留摘要和日志路径；全量测试输出、产物清单和视觉附件存文件。
- token 紧张时停在阶段边界，提交可审查的差异/记录并列出未完成项；不靠降低验收
  标准宣称完成。下一阶段和全目标扩展不因当前阶段通过而自动获得执行授权。

## 9. 回滚与停止条件

旧生产路径在试点验收前保留，切换范围必须可定位、可回退；迁移目标的失败不得
通过静默 fallback 掩盖。已上线页面仍对应原发布快照，架构 PR 不自动触发重新发布。

出现内容遗漏、跨语言串图、包外内容读取、未解释的版式变化、历史包读取失败，
立即停止扩展并定位当前阶段。若工作量变为预计约三倍，报告新增范围后再由操作者
决定拆分或继续；不将新增型号、语言、模板重写、数据治理或发布流程改造混入本轮。

回退优先撤销尚未发布的试点接入或恢复既有入口，保留失败包及诊断证据。
不删除用户 `_build`、`_review`、发布产物或其他 worktree；不以改业务数据掩盖解析差异。
