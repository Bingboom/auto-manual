## 1. 总体判断与边界

系统已有内容治理、冻结快照、页面组装、构建渲染、审核发布的完整主干。成熟度不均：
基础机制已有真实使用，跨机型交付覆盖、公共整本生产入口及持续运营证据仍需收口。
下一阶段以“一本说明书的完整闭环能否稳定复用”衡量进展，不以文件数、配置数、
组件绑定数或某个成功样例代替全部产品成熟度。

沿用 [System Evolution Strategy](../architecture/System%20Evolution%20Strategy.md)
与 [内容归属规则](../architecture/Long_Form_Content_Block_Design.md)：

- 参数、复用短文案和参考表由结构化内容管理；译文和术语在各自规范库维护。
- 章节组合、版式与样式由骨架、模块和配置管理；稳定长文及法规正文按既有归属保留
  在受控模板，不以“全部搬入多维表”为完成目标。
- 设计母版与发布导出物独立保留，通过资产身份、来源、修订及哈希关联。
- 构建消费已确认且冻结的内容；模糊翻译候选不能直接成为发布时的动态输入。
- Web 与 IDML 共用内容语义和来源，分别管理响应式呈现与物理分页。
- 业务渠道和执行入口复用现有 `build.py`、队列及 [双平面边界](../../user-guide/two_plane_map.md)。

目标链路：

```text
结构化内容 + 已确认译文/术语 + 骨架/模块/目标配置 + 版本化资产
    → 目标组装与冻结 → 公共说明书语义包
        → Web 呈现与发布
        → IDML 排版与设计交付
    → 审核修订 → 归属判定 → 内容 / TM / 模板 / 资产来源
    → 受影响目标清单与可审核的更新
```

## 7. 成效指标及计算口径

先记录可比基线，再对一个真实试点比较。按目标结构、语言、输出端和资料齐套程度
分组，不把两种难度不同的说明书直接比较；建议目标不等于已实现收益。

| 希望带来的成效 | 指标与口径 | 证据来源 |
| --- | --- | --- |
| 新产品接入更快 | 资料齐套到首个可审核版本耗时；同时单列人工操作时间与等待时间；新增代码/模板复制量 | intake/目标状态、Git diff、实际操作记录 |
| 翻译复用提高 | 已复核精确命中单位数 / 符合口径的翻译单位总数；参数/模糊候选采纳率另列；译后修改量 | 预翻译报告、TM 来源和复核结果；候选命中不等于最终可用 |
| Web/IDML 内容一致 | 同目标同冻结版本的参数、正文、警告和资产身份中未解释差异数 | IR/组件清单、来源映射及实际两端输出；不比较像素或总页数相等 |
| 设计交付更稳定 | 母版回取与编辑成功率、错版本事件数、找图耗时 | 资产清单、设计编辑/重开、构建选择证据 |
| 审核成果可复用 | 有来源落地且复核通过的已接受修订 / 已接受修订总数；长期待处理项及年龄 | revision ledger + 回写/合入/重比对证据；`1-pending/total` 仅表示已有处置，不能直接当成功回流率 |
| 多产品维护成本下降 | 一次共享修改到需更新目标均被处理的耗时、人工次数和冲突数 | 影响清单、传播 PR、审核/冻结版本记录 |
| 用量可控 | 每次接入或修订的可取得 token/额度消耗、重复调查和重试次数 | 模型/任务用量与阶段记录；未取得数据记 unavailable，不从消息数估算 |
| 操作者负担下降 | 每本已发布说明书的介入次数及原因：内容判断、资料补齐、异常排查、机械操作 | 阶段记录/队列事件；明确哪些属于必要判断、哪些可减少 |

复用现有报表、账本和 manifest，先有可核验数据再考虑界面或仪表盘。不重复维护
同一批人工统计；没有基线时不承诺固定节省比例、工期或 token 预算。

## 8. 更新与销账纪律

每个子项记录：`债务 ID / 目标与语言 / 源与资产版本 / 负责人或任务 / 当前状态 /
实现 PR 与合入提交 / 实际验收 / 指标口径与样本 / 剩余限制 / 回滚点 / 下一步`。

- 发生新发现时追加范围与证据，不能覆盖历史验收来消除差异。
- 已完成的工程项保持其完成记录；新的覆盖或运营缺口另记子范围，不从零重开。
- 一个样例通过只关闭该样例范围；全库比例必须有明确分母、日期与匹配方法。
- 本轮只做文档检查；未来实现阶段按根 [AGENTS.md](../../AGENTS.md) 运行适用检查。
- 真正完成工作流或阶段时再更新 [维护日志](../code_optimization_log.md)，本次不记
  “平台化完成”“全产品同源”或“回流已打通”。
