# 产品信息矩阵 base（product matrix base）

Status: active（建设中，REV-50，登记见 PR #1734）· Owner: 夏冰 · Created: 2026-11-16

产品信息矩阵是一组飞书多维表，建在「发布文档管理」base 里，和该 base 原有的表并列，
不改动原有的任何表。它把已发布网页说明书规格表里的每个数值存成一条带出处、带时间、带核实状态的事实，
再按型号 × 市场生成一张矩阵视图。它长期维护，也是独立的竞情分析系统的底座。

定位依据：[Hello-Docs 定位](../architecture/Hello_Docs_Positioning.md) §4（保留原文与出处，核验前只是派生候选，
不能取代 PLM 等企业权威事实）与 §6（已发布内容形成的派生视图）。表结构清单：
[`bitable_schema/product_matrix_base_manifest.json`](../../bitable_schema/product_matrix_base_manifest.json)；
工具：[`tools/product_matrix_base/`](../../tools/product_matrix_base/)。

## 1. 五张表

表之间用**文本键**关联，键由工具写入。关联字段（link）只为界面好看，由人手工建，或者在证明写入能保存
（写后读回）之后再由工具写：仓库的多维表经验是关联字段写入可能报成功却没保存。

| 表 | 一条记录 | 主字段 | 内容 |
| --- | --- | --- | --- |
| 产品 | 一个型号在一个市场（同一型号跨两代时再加代际） | 产品键 `<型号>/<市场>` | 品牌、商品简称、类别、系列、容量档、名称、上市与停售、阶段、仅飞书的项目号、预留的关联 SKU |
| 属性 | 一个属性 | 属性键（稳定的 snake_case） | 中英文名、分组、值类型、规范单位、定义、适用类别、说明书通常写、各语言标签别名、竞情字段名、状态、排序 |
| 来源 | 一份来源文件的一个版本 | 来源键，如 `web/<型号>/<市场>/<语言>/<版本>` | 来源类型、型号、市场、语言、版本、版本日期及其依据、页面或文件、文件哈希、读取时间 |
| 事实 | 一个数值在一个来源里 | 事实键 `<产品键>\|<属性键>\|<条件键>\|<来源键>` | 原文、数值（规范单位）、文本值、原单位、限定、条件、来源位置、生效时间、记录时间、核实状态与核实人、当前值、冲突、裁定、取代者 |
| 矩阵 | 一个产品键 | 产品键 | 生成、只读：身份列、每个启用属性一列（最佳当前值，带单位，未核实的加标记）、当前值数、候选数、冲突数 |

- 属性键沿用自有产品事实导出的 9 个键（[`tools/product_facts/attributes.json`](../../tools/product_facts/attributes.json)），
  不改名；新增属性在 [`tools/product_matrix_base/attributes.json`](../../tools/product_matrix_base/attributes.json) 定义，
  其中标为 `export` 的项只引用导出的定义。
- 条件键：同一来源对同一属性按条件（如太阳能板的 STC / BNPI 列）写多个值时区分它们；无条件时为 `-`。
- 事实**不覆盖**：数值变了就是新来源（新版本）下的新一行；旧行由人标 已取代 并填 取代者。
- 品牌字段保留；竞品行是否进同一 base 尚未决定，目前只装自有品牌。

## 2. 谁写哪个字段

| 字段 | 写入者 |
| --- | --- |
| 产品键、型号、市场、品牌、商品简称、类别、系列、容量档、名称、共用说明书于、最后更新 | 装载工具（类别等取自产品分类快照；快照没有的留空，不猜） |
| 代际、上市日期及依据、停售日期、产品阶段、项目号（仅飞书）、关联 SKU、SKU 最早创建时间、备注 | 人 |
| 属性表全部字段 | 装载工具首次写入（字典），之后由人维护；工具不改已存在的属性行 |
| 来源表全部字段 | 装载工具；版本日期及依据在已知时由人补 |
| 事实：键、产品键、属性键、来源键、原文、数值、文本值、原单位、限定、条件、来源位置、记录时间 | 装载工具 |
| 事实：核实状态 | 工具只写 `候选`；已核实 / 有疑问 / 已驳回 / 已取代 由人写 |
| 事实：核实人、核实时间、裁定说明、取代者、生效起、生效依据、生效止 | 人 |
| 事实：当前值、冲突、冲突说明 | 重算工具（下一步，见 §6） |
| 矩阵表 | 重算工具生成，人不编辑 |

## 3. 时间模型

每个数值区分**生效时间**和**记录时间**：

- 记录时间：工具写入该行的时间（北京时间）。
- 生效起 / 生效止：这个数值在产品上何时成立。来源版本日期已知时才填；未知留空，不估计。
  之后由操作者从同一 base 的 PLM 导出表（按 SKU，含创建时间）回填：产品表的「关联 SKU」和
  「SKU 最早创建时间」为此预留。2026-11-16 机器人在 `SKU（plm数据）` 表上看不到创建时间字段，
  所以「SKU 最早创建时间」先建成空的日期字段，由操作者决定改成查找引用还是手填。
- 来源的版本日期依据只能是 审批日期 / 归档日期 / 规格书版本日期 / 首次网页发布 / 未知；
  网页构建时间不等于以上任何一种，只写在来源的备注里，依据记为 未知。

## 4. 最佳当前值与核实

矩阵的「最佳当前值」= 最新的 已核实 行；没有已核实行时，取来源排名最高的最新 候选 行，并标为未核实。
未经任何人核实的数值照样进矩阵，带未核实标记；核实逐步进行，记录在 base 里，不回写仓库。

## 5. 写入与读取路径

```bash
# 1. 抽取：读发布清单列出的每个语言版本，输出到 git 工作树以外
python -m tools.product_matrix_base extract --root <Hello-Docs 检出> --out <仓库外>/extraction.json
# 2. 预演：各表待新建行数、已存在不动的行数、字段与选项预检
python -m tools.product_matrix_base stage --extraction <...>/extraction.json --root <Hello-Docs 检出> \
    [--models A,B] [--markets US,EU] [--attributes k1,k2] --profile <lark-cli profile> --report <仓库外>/plan.json
# 3. 写入：预演结果经操作者在窗口确认后
python -m tools.product_matrix_base stage ... --write --yes
```

- base 由 `--base-token` 或环境变量 `FEISHU_PUBLISHED_DOCS_BASE_TOKEN` 指定，身份默认 bot。
- 抽取：规格表按类名（`spec-table`、`native-spec`）或多语言规格标题识别；每一行原样保留标签和文字、
  解析出的数值与单位、章节路径、锚点、表号与行号。没有属性认领的行照样保留，列入 `unmapped`。
  同一型号同一市场的各语言版本逐属性比较，写法不一的列入 `differences`。
- 导出的 9 个键用自有产品事实导出的读表规则（`read_facts`）读，喂给它的是抽取器找到的全部行，
  所以导出原读法漏掉的版式（如日文 td/td 表）也能读到；这套规则只认英、中、日标签。
- 写入：只新建主字段值不存在的行，已存在的行一律不动，所以重跑是空操作；每批不超过 100 行
  （CLI 上限 200）；写前预检字段名与单选选项，不符即整体停止；写后按主字段把每一行读回，
  逐字段比对，报告缺失与不符，记录 id 只写进仓库外的报告文件。
- 只写这五张表；工具拒绝把抽取结果、计划和读回报告写进任何 git 工作树。

## 7. 不进 git 的内容

不进 auto-manual（公开仓库）、它的 PR、issue 或消息：base 里的任何记录值、SKU、项目号、table id、
base token、凭据、邮箱、内部网址；从说明书读出的产品数值（抽取结果、计划、读回报告）；
来源版本里的流水线构建标签（含提交哈希和内部批次号，只留在飞书里）。本仓库只放代码、表结构清单、
属性字典和虚构的测试样例。
