# 产品信息矩阵 base（product matrix base）

Status: active（建设中，REV-50，登记见 PR #1734）· Owner: 夏冰 · Created: 2026-11-16

产品信息矩阵是一组飞书多维表，建在「发布文档管理」base 里，和该 base 原有的表并列，
不改动原有的任何表。它把已发布网页说明书规格表里的每个数值存成一条带出处、带时间、带核实状态的事实，
再按型号 × 市场生成一张矩阵视图。它长期维护，只收自有产品。

定位依据：[Hello-Docs 定位](../architecture/Hello_Docs_Positioning.md) §4（保留原文与出处，核验前只是派生候选，
不能取代 PLM 等企业权威事实）与 §6（已发布内容形成的派生视图）。表结构清单：
[`bitable_schema/product_matrix_base_manifest.json`](../../bitable_schema/product_matrix_base_manifest.json)；
工具：[`tools/product_matrix_base/`](../../tools/product_matrix_base/)。

## 0. 价值定位（操作者，2026-11-16）

以项目为索引、以产品属性为核心、以时间为维度，持续整合说明书中的产品技术信息，建立可查询、可比较、可追溯的产品信息矩阵。

通过集中管理分散在历史文档中的产品信息，降低信息查找、重复整理与人员交接成本，为说明书开发、产品信息复用及后续跨业务分析提供可靠的数据基础。

## 1. 五张表

表之间用**文本键**关联，键由工具写入。关联字段（link）只为界面好看，由人手工建，或者在证明写入能保存
（写后读回）之后再由工具写：仓库的多维表经验是关联字段写入可能报成功却没保存。

| 表 | 一条记录 | 主字段 | 内容 |
| --- | --- | --- | --- |
| 产品 | 一个型号在一个市场（同一型号跨两代时再加代际） | 产品键 `<型号>/<市场>` | 品牌、商品简称、类别、系列、容量档、名称、上市与停售、阶段、仅飞书的项目号、预留的关联 SKU |
| 属性 | 一个属性 | 属性键（稳定的 snake_case） | 中英文名、分组、值类型、规范单位、定义、适用类别、说明书通常写、各语言标签别名、竞情字段名、状态、排序 |
| 来源 | 一份来源文件的一个版本 | 来源键，如 `web/<型号>/<市场>/<语言>/<版本>` | 来源类型、型号、市场、语言、版本、版本日期及其依据、页面或文件、文件哈希、读取时间 |
| 事实 | 一个数值在一个来源里 | 事实键 `<产品键>\|<属性键>\|<条件键>\|<来源键>` | 原文、数值（规范单位）、文本值、原单位、限定、条件、来源位置、生效时间、记录时间、核实状态与核实人、当前值、冲突、裁定、取代者 |
| 矩阵 | 一个产品键 | 产品键 | 生成、只读：项目号、身份列、上市日期（有值时）、每个有值的启用属性一列（最佳当前值；数值属性为数字列，单位在列名）、来源、事实数、已核实数、候选数、冲突数、组件事实数、空缺数值数、生成时间（§4.1） |

- 属性字典共 140 项，首次装载的内容在 [`tools/product_matrix_base/dictionary.json`](../../tools/product_matrix_base/dictionary.json)；
  装载后属性表在飞书里维护，工具只补不存在的属性。自有产品事实导出的 9 个键
  （[`tools/product_facts/attributes.json`](../../tools/product_facts/attributes.json)）沿用不改名。
- 条件键：同一来源对同一属性按条件（如太阳能板的 STC / BNPI 列）写多个值时区分它们；无条件时为 `-`。
- 事实**不覆盖**：数值变了就是新来源（新版本）下的新一行；旧行由人标 已取代 并填 取代者。
  唯一例外是工具自己读错的候选：来源和原文没变、只是读法改正了，且这一行仍是 候选（没人核实过），
  才在原行上修正读出的字段，写入批次改为这次修正的标签，旧值记进备注；原文和核实状态不动（操作者 2026-11-16 确认）。
  能改的字段只有 文本值 和 原单位（原单位可以清空，文本值不行）；差异还涉及数值、限定、条件、来源位置的行，
  或修正会清空文本值的行，整行不改，列入「需人决定」。写入前再查一次核实状态，已不是候选的跳过。
- 矩阵只收自有产品，竞品数据目前不做（见定位 §4.2）；品牌字段保留，只有 `自有` 一个选项。
- 来源和事实都有「写入批次」：一次性读取装入的行标明批次，正式抽取工具接手后可据此分辨和取代。
- 属性键的改名对照（种子字典 v0 键 → 最终键，140 个，不含数值）在
  [`tools/product_matrix_base/attribute_key_renames.json`](../../tools/product_matrix_base/attribute_key_renames.json)。

## 2. 谁写哪个字段

| 字段 | 写入者 |
| --- | --- |
| 产品键、型号、市场、品牌、商品简称、类别、系列、容量档、名称、共用说明书于、最后更新 | 装载工具（类别等取自产品分类快照；快照没有的留空，不猜） |
| 代际、上市日期及依据、停售日期、产品阶段、项目号（仅飞书）、关联 SKU、SKU 最早创建时间、备注、不收录 | 人 |
| 属性表全部字段 | 装载工具首次写入（字典），之后由人维护；工具不改已存在的属性行 |
| 来源表全部字段 | 装载工具；版本日期及依据在已知时由人补 |
| 事实：键、产品键、属性键、来源键、原文、数值、文本值、原单位、限定、条件、来源位置、记录时间 | 装载工具 |
| 事实：核实状态 | 工具只写 `候选`；已核实 / 有疑问 / 已驳回 / 已取代 由人写 |
| 事实：核实人、核实时间、裁定说明、取代者、生效起、生效依据、生效止 | 人 |
| 事实：当前值、冲突、冲突说明 | 重算工具（下一步，见 §6） |
| 矩阵表 | 重算工具生成，人不编辑 |

## 3. 时间模型

每个数值区分**生效时间**和**记录时间**：

- 记录时间：工具写入该行的时间（北京时间）。
- 生效起 / 生效止：这个数值在产品上何时成立。来源版本日期已知时才填；未知留空，不估计。
  之后由操作者从同一 base 的 PLM 导出表（按 SKU，含创建时间）回填：产品表的「关联 SKU」和
  「SKU 最早创建时间」为此预留。2026-11-16 机器人在 `SKU（plm数据）` 表上看不到创建时间字段，
  所以「SKU 最早创建时间」先建成空的日期字段，由操作者决定改成查找引用还是手填。
- 来源的版本日期依据只能是 审批日期 / 归档日期 / 规格书版本日期 / 首次网页发布 / 未知；
  网页构建时间不等于以上任何一种，只写在来源的备注里，依据记为 未知。

## 4. 最佳当前值与核实

矩阵的「最佳当前值」= 最新的 已核实 行；没有已核实行时，取来源排名最高的最新 候选 行，并标为未核实。
未经任何人核实的数值照样进矩阵；按行给出已核实数与候选数代替逐格标记（§4.1）。核实逐步进行，记录在 base 里，不回写仓库。

## 4.1 矩阵表的生成

`python -m tools.product_matrix_base matrix`（默认预演，`--write --yes` 才写）从 base 里的产品、属性、事实、来源
生成矩阵表：

- 一个产品键一行，按产品键新建或更新；产品表里已没有、或被人勾了「不收录」的产品，常规刷新只在预演里把其矩阵行列为
  「可删候选」（产品键和行数），从不顺带删除：生成的计划默认不删任何行，直接写入计划的调用方也不会删；要删须用
  `--remove-row <产品键>`（可重复）逐行指定，且只能指定候选行，预演另列「本次删除」；写后读回确认已删、打印被删的
  产品键，并核对行数（写前行数 − 删除 + 新建），不符则以非零退出。产品表没有「不收录」字段时（被改名或删除）
  矩阵和快照都停止，而不是把被排除的产品放回来
  （操作者 2026-11-17 决定：删矩阵行，事实和来源保留不用）。「不收录」由人在产品表勾选：产品行保留（装载工具据此不再把它加回来），
  它的事实和来源行留在表里但不再使用——矩阵和快照都不读它们。除此之外不删行；身份列之后，每个启用且至少有一个值的属性一列，按字典排序，
  列名用中文名。值类型为数值或整数的属性建数字列，规范单位写进列名，可排序筛选；其余为文字列。
- 项目是首要索引：矩阵的 `项目号` 列紧跟主字段，取自产品表的「项目号（仅飞书）」，可按它分组查看；
  一个项目通常包含多个型号 × 市场行，行粒度不变。`python -m tools.product_matrix_base projects`
  （默认预演）按型号从同一 base 的「网页文档」表查项目号，只给仍为空、且只对应一个项目的产品补上；
  对到多个项目或查不到的产品由人填写；已有项目号但与网页文档不同的，不改，按产品键列出。项目号只在飞书、私有仓库 Hello-Docs
  （§6.1 的快照）和需登录的私有站点之间流转，从不进公开仓库 auto-manual、它的 PR 与 CI 日志或公开站点（§7）：
  命令输出、报告文件、本仓库和 PR 都只有产品键和计数；带项目号的写入失败时，只报操作、产品键和 lark-cli 错误码，
  不转出 CLI 的错误原文（它可能回显载荷）。写到一半失败时，已写的照样读回，按产品键报告，命令以非零退出。
- 时间：上市时间（产品.上市日期，人填并写依据；SKU 创建时间不是上市时间，见下一条）、数值生效时间（事实.生效起/止）、记录时间
  （事实.记录时间、来源日期）三者不混。产品表有上市日期后，矩阵自动加 `上市日期` 列；在此之前矩阵只有 `生成时间`。
- SKU 创建时间：产品表的公式字段「SKU 最早创建时间（本市场）」取「父-子物料映射」中项目号相同、区域包含本产品市场的
  SKU 里最早的 sku创建时间；没有匹配为空，不报错。它表示产品在 PLM 里出现的时间，**不是上市日期**：工具只读不写它，
  也从不把它复制进上市日期；要拿它当某个产品的上市日期，由人填上市日期并写明上市日期依据。PLM 的数据从 2023 年底
  导入开始，所以不晚于 2023-12-31 的时间只是上限（产品那时已存在，可能早得多），不当作产品的起点。
  有值后矩阵加 `SKU 最早创建时间` 列；快照里是 `first_sku_created`，带依据 `first_sku_created_basis` 和上限标记
  `first_sku_created_upper_bound`，与 `launch_date` 分开（操作者 2026-11-17）。
- 可追溯：每行的 `来源` 列写出该行数值取自的说明书页面，`事实数` 写出事实表里该产品可回查的事实条数；
  回查路径是事实表按 产品键 + 属性键 筛选。
- 每格是最佳当前值（§4）。组件事实（条件 `组件:…`）和 已驳回 / 已取代 的事实不进格子；组件事实按行计数。
- 数字列只收有数值、且原单位就是该列规范单位或能换算成它的事实；否则留空，按原因（无数值 / 单位与列不符）
  计入「空缺数值数」，清单写进仓库外的报告。文字列遇到只剩一个数值区间、而原文是功率行的值时，填原文所印文字。
- 数字格不能带「未核实」标记，所以每行给出 已核实数 / 候选数 / 冲突数：已核实数为 0 的行里每个值都是候选。
- 写后按产品键读回逐字段比对；生成时间只随行内容变化而更新，事实不变时重跑没有要写的。
  `--drop <列名>`（可重复）只按名删列：该列已不由生成器产生、每一行都为空、且本次写入读回无缺失无不符时才删；
  从不按「多出来的列」整批删，人在飞书里加的列不会被动。读取宽表时每次最多投影 50 个字段（CLI 限制），
  工具分批读取后按记录合并。表结构清单里的矩阵字段由 `--manifest` 按生成的列改写。

## 5. 写入与读取路径

```bash
# 1. 读取：读发布清单列出的每个语言版本，输出到 git 工作树以外
python -m tools.product_matrix_base read --root <Hello-Docs 检出> --out <仓库外>/reading.json
# 2. 预演：各表待新建行数、已存在不动的行数、已存在但本次读法不同的行、字段与选项预检、出处检查
python -m tools.product_matrix_base stage --reading <...>/reading.json --root <Hello-Docs 检出> \
    [--models A,B] [--markets US,EU] [--batch <写入批次>] --profile <lark-cli profile> --report <仓库外>/plan.json
# 3. 写入：预演结果经操作者在窗口确认后；--correct 同时原地修正读法不同的候选事实
python -m tools.product_matrix_base stage ... --write --yes [--correct]
```

- base 由 `--base-token` 或环境变量 `FEISHU_PUBLISHED_DOCS_BASE_TOKEN` 指定，身份默认 bot。
- 产品表勾了「不收录」的产品，装载时它的产品、来源、事实行一律跳过，不再新建也不比对；预演列出跳过的行数
  （操作者 2026-11-17：产品行保留以免被加回来，已有的事实和来源留着不用）。产品表没有「不收录」字段时装载停止，
  与矩阵、快照一致；出处检查在跳过之后进行，保留产品的事实若引用被跳过的来源，会在写入前列为问题
  （读取器按事实自己的型号 × 市场 × 语言取来源，目前不会产生这种跨产品引用）。
- 读取（[`tools/product_matrix_base/reader/`](../../tools/product_matrix_base/reader/)）：规格表按多语言规格标题与其
  同级分组标题、规格类名（`spec-table`、`native-spec`）和 `spec-row` 列表识别；规格节以外的充电时间、保修、
  装箱清单等规格类表也读。每一行原样保留标签、值、列名、章节路径与锚点；标签按各语言规则映射到属性，
  没有端口方向的标签只在小标题写明输入或输出时才映射；没有规则认领的行照样保留，列入 `unmapped`。
- 事实：每个型号 × 市场取一个主语言版本（英文，否则市场主语言，见 `reader/market_languages.json`，
  否则行数最多的版本），同一属性的多行合成一个值；其他语言版本只做比对，结论写进备注，不合并。
  日规「サイズ＆重量」一行同时读尺寸和重量。说明书里随附或另售组件的表（电池包、转换开关、太阳能板）
  按「产品名称」行分块，主产品以外的块记为组件事实。派生数值（整机 AC 输出、峰值、口数、输入上限等）
  只从印出的文字读，备注写明来自哪几行。功率类行没印瓦数时，文本值保留原文，不写成电压区间。
- 出处检查：每条事实的来源键必须是暂存或 base 里的来源行，且该来源是 网页说明书、键与发布清单
  中的某个发布一一对应；否则整批拒写（`--staged` 也一样）。规格书、PLM 等新来源类型接入时各加自己的检查，
  不放宽这一条。
- 写入：只新建主字段值不存在的行，已存在的行一律不动，所以重跑是空操作；每批不超过 100 行
  （CLI 上限 200）；写前预检字段名与单选选项，不符即整体停止；写后按主字段把每一行读回，
  逐字段比对（日期时间比到秒），报告缺失与不符，记录 id 只写进仓库外的报告文件。输出路径在任何写入之前检查；
  某一批失败时，已写进去的行照样读回并报告，操作者能知道 base 停在什么状态。
- 只写这五张表；工具拒绝把抽取结果、计划和读回报告写进任何 git 工作树。

## 6.1 私有站点用的快照

私有站点（登录后才能看）的产品页面——产品库、单品页、对比页、表格视图——从 base 读产品信息，
不再从各本说明书里用正则读。为此 base 的内容以快照形式进入私有仓库 Hello-Docs，私有站点构建时读它。

- 命令：`python -m tools.product_matrix_base snapshot [--out <Hello-Docs 检出>/docs/knowledge/product-matrix] [--write]`。
  只读 base；默认只打印计数，加 `--write` 才写出 `snapshot.json`（不叫 `product_matrix.json`，以免和门户的同名配置文件混淆）。
- 内容（`hello-docs-product-matrix-snapshot/v1.1`，v1 之上只增加 `values[].id` 与 `cells`；每个列表按键排序，两次快照可直接 diff）：
  - `products`：产品键、型号、市场、品牌、商品简称与各语言名称、类别、系列、容量档、项目号、上市日期等；
  - `parameters`：属性键（只作关联用）、中英文名、分组、值类型、规范单位、定义、适用类别、排序；
  - `sources`：不透明的来源 id（来源键的哈希）、来源类型、型号、市场、语言、版本日期、页面路径（链到已发布说明书）；
  - `values`：每个产品 × 参数 × 来源一条：原文、数值、文本值、原单位、限定、条件、来源位置、核实状态、
    当前值、冲突，以及同一产品同一参数的不同来源是否写法不一（`sources_disagree`）；
    单位：`number` 和 `text` 是规范化后的值，单位一律是该参数的规范单位（`parameters[].unit`）；`printed` 与
    `printed_unit` 是说明书原样印的文字及其单位（例如原文写 cm，规范化后的尺寸文本是 mm）。页面显示值时读
    `number`/`text` 配 `parameters[].unit`，`printed`/`printed_unit` 只用于「说明书原文」的对照；
  - `cells`（v1.1 起）：矩阵选定的那一格，每个产品 × 启用的参数一条（STC、NOCT、BNPI 这类测试条件各占一格，
    循环次数等其他条件并入主格），页面只负责显示，不自己挑值。取值与矩阵相同（[`cells.py`](../../tools/product_matrix_base/cells.py)
    复用 `matrix._rank` / `_cell`）：已驳回、已取代不参与；先已核实，再按来源类型，再取记录时间最新。每格给出
    `display`（与矩阵那一格相同）、`number`（规范单位下的数值，供排序）、`text`、`unit`、选中那条的 `printed` /
    `printed_unit` / `source` / `value`、`verified`、`sources_disagree`、`conflict`、参与的全部 `candidates`（按取值顺序，
    第一个即选中），数字格没有可用数值时 `display` 为空并给 `empty_reason`。纯范围文本的功率行显示原文。
    组件事实不进 cells；一个参与值都没有的格子不生成。`values` 与 `component_values` 每条带不透明 `id`
    （事实键的哈希），cells 用它引用。
    - `display` 是页面可直接显示的完整文字：与矩阵那一格相同，只是数字后面多带参数单位（矩阵把单位放在列名里），
      整数不带「.0」，单位为空时不加；文本照矩阵；纯范围文本的功率行（文字参数）显示原文；空格为 null 并带 `empty_reason`。
    - 两个 `sources_disagree` 含义不同：`values[]` 上的按（产品、参数）跨所有条件算；`cells[]` 上的只看这一格参与的值，
      数值按数字比较（100 与 100.0 相同）。页面用 cells 上的。
    - 与矩阵的一处差别：矩阵按（产品、参数）只取一格；快照给 STC、NOCT、BNPI 各开一格（条件名前后不是字母即可，
      如「STC条件」）。某参数的事实如果全带测试条件，矩阵显示其中排第一的，快照没有主格（`condition` 为 null 的格），
      只有条件格；页面要按条件格显示。
    - 写快照前校验引用：`values` / `component_values` 的 id 在文件内唯一，cells 的 `value`、`candidates`、`source`
      全部能解析，`candidates` 无重复；不满足就停止，只报数量。
    - 先后顺序：门户读取器接受 v1.1（并继续接受 v1）之前，不把 v1.1 的快照写进 Hello-Docs，否则产品页读不到数据；
  - `component_values`：组件的值，单列，不并入主产品；
  - 勾了「不收录」或已从产品表删除的产品不进快照，它们的值不进 `values` / `component_values`；
    `sources` 不含这些产品的来源（被收录产品的来源即使暂无值也保留）；
  - 头部：读 base 的时间、各表计数、快照 schema。
  不含飞书 record id、table id、token、网址，也不含来源版本标签（含流水线构建号）：来源只用不透明 id 和页面路径。
- 写入位置由代码把关，两个条件同时满足才写：检出的 `origin` 远端指向 Hello-Docs 仓库（读不到远端就拒绝），
  且根 README 等于 `mirrors/Hello-Docs/README.md`（与维护性守卫识别镜像的方法相同；`origin` 指向 auto-manual 的检出
  不论 README 如何都不算镜像，守卫也按这条判断）；目标还必须在 `docs/knowledge/` 下。目标文件是符号链接时拒绝，
  写入先写同目录临时文件再改名。命令打印的摘要只有计数；读写带项目号的表失败时，只报操作和 lark-cli 错误码，
  不转出 CLI 的原始输出。
- 每个产品都有 `project` 字段（没有项目号时为 null）；对到多个项目的产品不会被随便选一个，保持为空，由人在 base 里填。
- 刷新：base 有改动后在 Hello-Docs 检出上重跑命令，以 Hello-Docs 的内容 PR（只含该目录）提交。

## 7. 不进 git 的内容

不进 auto-manual（公开仓库）、它的 PR、issue、CI 日志或消息，也不进公开站点：base 里的任何记录值、SKU、项目号、
table id、base token、凭据、邮箱、内部网址；从说明书读出的产品数值（抽取结果、计划、读回报告）；
来源版本里的流水线构建标签（含提交哈希和内部批次号，只留在飞书里）。本仓库只放代码、表结构清单、
属性字典和虚构的测试样例。

项目号可以进入私有仓库 Hello-Docs（`docs/knowledge/` 下的快照）和私有站点（操作者 2026-11-17：
「放开到私有站点和私有仓库」）；除此之外的规则不变，也不在对话输出里打印项目号。
