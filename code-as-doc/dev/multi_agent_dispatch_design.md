# 多 Agent 调度与任务续接设计

- 状态：定稿，2026-09-25（第 5 节已由操作者回答）。
- 2026-09-25 起，本稿第 3 节的做法已被 [agent_task_state_design_2026-09.md](agent_task_state_design_2026-09.md) 取代（操作者按建议确认），不再作为实施依据；第 1、2 节的背景仍可参考。
- 台账：[REV-45](manual_revitalization_execution.md#rev-45)，依赖已验收的 [REV-44 来源登记](ssot_source_registry_design.md)。
- 来源：系统建设页“Agent 执行”卡写着“多 Agent 调度与任务续接尚未建设”；操作者 2026-09-25 决定先记进台账，出设计后再建。

## 1. 现在已有什么

| 已有 | 管什么 | 缺什么 |
| --- | --- | --- |
| 执行台账（REV 行、第 4 节续接点、第 1 节第 7 条“可续接”） | 任务、依赖、状态、证据、每轮续接记录 | 没有“谁正在做”的认领记录；台账写明“不是自动调度器” |
| `AGENTS.md` 第 8 节 | 多窗口规则：一窗口一 worktree、一任务一分支、不碰别人的文件 | 只管不打架，不管派活和交接 |
| 合并授权登记表（MA 行） | 哪个 PR 可以由 agent 合入 | 编号靠手工取下一个，并行窗口会撞号 |
| 来源登记（REV-44） | 每类事实以哪里为准、多久算过期 | 还没有“任务状态”这个数据域 |
| 各 agent 自己的记忆 | 单个 agent 的经验和进度 | 别的 agent 和别的主机读不到 |
| 聊天派发（OpenClaw / BlockClaw） | 在聊天里触发构建、发布 | 只派构建任务，不派开发任务 |

## 2. 要解决的问题

实际发生过的情况（2026-09 以来）：

- **撞号**：同一天里，登记表的授权编号被并行窗口先占了三次（MA-164、MA-166、MA-168），每次都要改号重推。
- **看不到谁在做**：别的窗口在我的分支上写授权行、合了我正要合的 PR；主检出停在别人早已合入的旧分支上一个月没人发现。
- **续接靠聊天记忆**：换窗口或上下文压缩后，要从聊天记录里重新找做到哪。

所以第一版只解决四件事：派给谁、谁在做、做到哪、下一个人怎么接。

## 3. 做法（第一版，不做自动调度）

### 3.1 任务状态只认一处

- 任务仍然是台账的 REV 行。新增一个来源登记数据域“任务状态”：权威来源是台账加交接记录；认领超过 7 天没有更新就算过期（第 5 节第 4 条）。
- 页面和 agent 都按登记去读，不各自保存一份副本。

### 3.2 认领

- 开始做一项之前，先在台账该行的“执行”格写上认领：`执行=<agent>（<窗口或主机>）<日期> 起；分支=<分支名>`。认领随这项任务的第一个 PR 进入 main。
- 已有认领、而且没过期的，其他 agent 不开工，先问操作者。
- 认领只写在台账里，用来让 agent 之间不重复开工；系统建设页不显示认领人（操作者：所有窗口都是操作者在派、在用）。

### 3.3 交接记录

每次停下来（一轮结束、上下文快满、换人），写一段交接记录，字段沿用 IR 迁移计划第 8 节：

| 字段 | 内容 |
| --- | --- |
| 基线 | 当前 main 或分支的提交号 |
| 已完成 | 做完的范围和对应 PR |
| 下一步 | 下一个具体动作 |
| 失败点 | 没解决的问题、已排除的方向 |
| 验证 | 已跑的命令和日志位置 |

交接记录写在任务 PR 的描述里，单独一节“交接”，停下来时更新；不新增文件。

### 3.4 续接

接手的 agent 只读四样东西，不重读全部历史：台账该行、最新交接记录、相关 PR 的当前状态、交接基线到 main 的增量 diff。

### 3.5 编号不再撞

新增一个只读小工具：同时查 main 和所有开着的 PR，给出登记表下一个空闲的 MA 编号（台账的 REV 编号同理）。推送前再查一次，被占了就换号。

### 3.6 派发

- 操作者在聊天里把某个 REV 派给某个窗口，或者由当前 agent 建议、操作者确认。
- 被派的窗口按 3.2 认领、按 3.3 交接。
- 第一版不做定时唤醒，也不做自动派发：这些需要改 workflow 或常驻服务，要操作者另外批准。

## 4. 验收

按台账 REV-45 的退出条件：用一条真实任务演示“派发 → 认领 → 交接 → 另一个窗口续接”，全程只靠台账、交接记录和 PR，不靠聊天记忆；不宣称自动调度已启用。

## 5. 操作者的决定（2026-09-25）

1. **交接记录写在任务 PR 的描述里**（「放在任务 PR 的描述里（推荐）」）。
2. **系统建设页不显示认领人**（「都是我啊」）：所有窗口都是操作者在派、在用，认领只在台账里供 agent 之间协调。
3. **做“取下一个编号”的只读小工具**（「做（推荐）」），先管登记表的 MA 编号，台账的 REV 编号同理。
4. **认领过期天数**：按草稿默认 7 天，写进来源登记的“任务状态”数据域；以后改只改那一处。
5. **演示任务用 REV-39 契约表冻结**（「REV-39 契约表冻结（推荐）」）：摸底结果出来后，本窗口在契约表 PR 的描述里写交接，另一个窗口只读台账、交接和 PR 接手完成冻结。
