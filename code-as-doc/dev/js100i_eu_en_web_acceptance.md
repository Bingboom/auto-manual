## Composition

`Solar@INTL` declares nine reusable body slots: Safety Tips, Inbox, product
views, unfolding, folding, charging connections, angle/device use,
specifications, and warranty. The resolved `manual_solar_eu_en` manifest emits
those slots in that order. It intentionally has no cover, TOC, LCD, UPS,
troubleshooting, or App carrier.

JS-100I copy lives in `docs/templates/page_solar/en/`; specification facts and
STC/BNPI notes use the same phase2 CSV contract as other manuals. For this
release, `data/manual_sources/JS-100I/EU/en/2.0/` is the explicit Git-tracked
structured-data input, validated against the current published V2.0 manual and
bound by `source_manifest.json`; it is not presented as a live Base snapshot.
Five Inbox items use
`HB-SPECIAL-INBOX/responsive-card-grid`; the unchanged three-card variant
remains the legacy default for existing manuals.

Thirteen English figure crops are generated by
`data/asset_recipes/manual_js100i_eu_en_web.json`, visually reviewed, and
locked by output SHA-256. `docs/renderers/web/js100i_eu_en_illustrations.json`
binds every figure to `(JS-100I, EU, en)`, both source hashes, and its original
master page/bounding box.

## Acceptance evidence

The target-specific test builds Web-profile MyST and verifies:

- Safety Tips is the first public-IR page and all nine slots are present;
- the Inbox has five ordered cards and the variable-card Web adapter;
- specifications include STC/BNPI values, subscript/superscript characters,
  notes, IEC category, and multifunctional-adapter outputs;
- all 13 figure bindings are used and each committed asset hash matches;
- a cold process replays `manual.ir.json` without reading any `.rst` or `.csv`;
- changing a packaged figure fails closed before render.

Local RTD-style Sphinx HTML completed without warnings. Browser acceptance
used a 375×812 mobile viewport and a 1440×900 desktop viewport. Both had zero
image overflow; the five-card Inbox resolved to one column on mobile and five
columns on desktop. The first visible chapter was Safety Tips in both views.

The formal lane consumes the versioned MyST/assets frozen package through
`tools/publish_branch_assembly.py` and advances only the shared Hello-Docs
`docs/publish/**` candidate PR. No direct Hello-Docs engineering-tree edit,
online queue dispatch, or live Base write is part of this target handoff.
